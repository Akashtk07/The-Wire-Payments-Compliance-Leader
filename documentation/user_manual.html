Introduction

What is The Compliance Leader?

An enterprise-grade ISO 20022 compliance platform for financial institutions migrating from SWIFT legacy MT messages to the modern MX (ISO 20022) standard.

🔄
MT → MX Translation
Convert SWIFT legacy messages to ISO 20022 XML with CBPR+ R2025 compliance
⬅️
MX → MT Reversal
Reverse-translate ISO 20022 XML back to SWIFT MT format
📚
Knowledge Base
AI-powered RAG system for SWIFT/ISO 20022 documentation queries
🧠
Prompt Lab
Interactive prompt engineering course with banking-domain examples
📄
Document Intelligence
Upload & query PDF/DOCX compliance documents using AI
🛡️
Audit & Telemetry
Immutable cryptographic audit trail with real-time event feed
🏦
Standards Compliance
Enforces CBPR+ R2025 (effective Nov 22, 2025) and LYNX (Canadian domestic) standards. All translations validated against official XSD schemas.

🖥️ Backend

  • Python / FastAPI on port 8000
  • JWT authentication (60-min access tokens)
  • ChromaDB vector store for RAG
  • lxml for ISO 20022 XML generation & XSD validation
  • SQLite + NDJSON for audit persistence

🌐 Frontend

  • Next.js (React) on port 3000
  • CodeMirror for syntax-highlighted XML editing
  • Server-Sent Events for real-time telemetry
  • JWT stored in localStorage + HttpOnly cookies
  • Middleware auth guard on all protected routes

Module 2 — Translation Modes

Partial vs Full Translation Mode

The Translation Mode toggle controls how strictly CBPR+ compliance rules are enforced.

🛡️ Partial (Strict) Mode
  • Halts on any CBPR+ rule violation
  • Returns HTTP 422 with detailed error
  • No XML output on errors — safe for production
  • Default mode when app loads
Error example: "ChrgBr value 'DEBT' not permitted at interbank level under CBPR+ R2025"
⚡ Full Translation Mode
  • Continues even with CBPR+ rule warnings
  • Generates ISO 20022 XML regardless
  • Warnings listed alongside XML output
  • Status shows PARTIAL instead of PASS
  • Ideal for: Testing, migration analysis
Use when you want to see the full XML even if the message doesn't fully comply yet.

📊 Validation Status Badges

BadgeMeaningAction
✅ PASSXML valid against XSD schema + all CBPR+ rules passXML is production-ready
⚠️ PARTIALXML generated but one or more CBPR+ warnings existReview warnings; fix before production use
❌ VALIDATION ERRORXSD schema validation failed — XML structure invalidCheck error details; correct MT input
🚫 ERRORMT parsing failed or network errorVerify MT raw text format is correct

Module 3 — MX → MT Engine

Reverse Translation: ISO 20022 → SWIFT MT

The MX → MT Engine at /mx-translate converts ISO 20022 XML back to SWIFT MT format. Supports two operating modes.

📋 Supported Input Types

ISO 20022 InputOutput MT
pacs.008.001.08MT103 (CBPR+ or LYNX)
pacs.009 COREMT202 / MT205
pacs.009 COVMT202 COV / MT205 COV
pacs.004.001.09MT103RETURN / MT202RETURN

🔄 Two Operating Modes

Mode 1: MX → MT Translation

Paste ISO 20022 XML → select type & scheme → Translate → receive raw SWIFT MT message

Mode 2: pacs.008 → Cover pacs.009

Convert a pacs.008 into its cover payment (pacs.009 COV) with a fresh UETR for correspondent banking flows.

🚀 Step-by-Step

  1. Click MX → MT Engine in the sidebar
  2. Select Mode: MX → MT or pacs.008 → Cover
  3. Select ISO 20022 message type
  4. Select Scheme: CBPR+ or LYNX
  5. Click Load Sample or paste your XML
  6. Click Translate →
  7. Raw SWIFT MT output appears in the right panel
  8. Copy or Download the result
🔍
UETR Rule in Cover Mode
Cover pacs.009 gets a new UETR; original UETR preserved as reference — follows CBPR+ cover payment chain guidelines.

Module 6 — Document Intelligence

Document Intelligence

Upload PDF or DOCX compliance documents at /documents and query them using AI-powered search.

📤 Uploading Documents

  1. Click Documents in the sidebar
  2. Drag & drop PDF/DOCX onto the upload zone, or click to browse
  3. Select a Guideline Set to categorize the document
  4. Click Upload & Index
  5. System splits document into chunks → stores in ChromaDB
  6. Document appears in the Indexed Documents list

🔍 Querying Documents

  1. Type your question in the Document Query input
  2. Or click one of the Example Queries for instant demos
  3. Press Search
  4. AI returns answer + shows which document chunks were used (with scores)
  5. Click any source citation to expand and read the exact text chunk

📋 Example Queries

  • "What are the mandatory fields for MT103?"
  • "Explain the CBPR+ settlement windows"
  • "What is the purpose of field 72 in SWIFT messages?"
  • "How is BIC validation performed?"
  • "Describe the ISO 20022 pain.001 message structure"

🗑️ Managing Documents

  • Each document shows: filename, chunk count, upload date, file type
  • Click Delete (🗑️) to remove document and its vectors from ChromaDB
  • Deletion is permanent — all associated search index entries removed
⚠️
Supported Formats
PDF and DOCX only. Large documents are automatically chunked into overlapping segments for better search precision.

Glossary

Glossary of Terms

TermDefinition
MTMessage Type — SWIFT's legacy financial message format (e.g. MT103)
MXMessage eXchange — ISO 20022 XML-based financial messages (e.g. pacs.008)
ISO 20022International standard for financial messaging using XML schemas
SWIFTSociety for Worldwide Interbank Financial Telecommunication
CBPR+Cross-Border Payments & Reporting Plus — SWIFT's ISO 20022 cross-border standard
LYNXHigh-value domestic payment system operated by Payments Canada
UETRUnique End-to-End Transaction Reference — mandatory UUID4 for all transactions
pacs.008ISO 20022: FI-to-FI Customer Credit Transfer (replaces MT103)
pacs.009ISO 20022: FI-to-FI Credit Transfer CORE/COV (replaces MT202)
pacs.004ISO 20022: Payment Return (replaces MT103RETURN/MT202RETURN)
TermDefinition
XSDXML Schema Definition — defines structure and rules for ISO 20022 XML
BICBank Identifier Code — 8 or 11 char bank identifier (e.g. DEUTDEBB)
IBANInternational Bank Account Number — standardized account format
ChrgBrCharge Bearer — who pays charges (SHAR=SHA, DEBT=OUR, CRED=BEN)
LLMLarge Language Model — AI model powering Knowledge Base and Prompt Lab
RAGRetrieval-Augmented Generation — combining document search with AI generation
JWTJSON Web Token — stateless authentication token for session management
OTPOne-Time Password — 6-digit email verification code on registration
SSEServer-Sent Events — real-time data streaming from server to browser
BAHBusiness Application Header — ISO 20022 envelope wrapping MX messages
